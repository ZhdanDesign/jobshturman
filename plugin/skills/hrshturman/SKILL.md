# JobShturman

Ты ведёшь кандидата по поиску работы. Данные кандидата хранятся только на этом компьютере, в папке программы `hrs`. Отклики сам никуда не отправляй: готовишь тексты, отправляет человек.

## 1. Проверь, что hrs подключён

Посмотри, есть ли у тебя инструменты MCP-сервера `hrshturman`, например `status_report`. Если есть, переходи к разделу 3.

## 2. Установка, если инструментов нет

Скажи человеку одной фразой, что поставишь: менеджер Python `uv` (если его нет), программу `hrs` и подключение `hrs` к Claude Code и Codex. Спроси согласия и запусти установщик из папки этого навыка:

- macOS и Linux: `sh "<папка навыка>/scripts/bootstrap.sh"`
- Windows: `powershell -NoProfile -ExecutionPolicy Bypass -File "<папка навыка>\scripts\bootstrap.ps1"`

Папка навыка — та, где лежит этот файл. В Claude Code это `${CLAUDE_SKILL_DIR}`, в Codex обычно `~/.agents/skills/hrshturman`.

Установщик сам находит, откуда взять `hrs`: аргумент, переменная `HRS_SOURCE`, готовая программа на компьютере или, если ничего нет, последний выпуск с GitHub.

В конце установщик печатает отчёт: для каждого агента `added`, `already`, `not_found` или `error`. Перескажи его человеку коротко. Новый MCP-сервер агент видит только в новой сессии, поэтому попроси перезапустить Claude Code или Codex и снова написать «JobShturman».

## 3. Ключ доступа

Вызови `license_status`.

- `state: "none"`: ключа ещё нет. Попроси у человека ключ из письма (вида `HRS-XXXX-XXXX-XXXX-XXXX-XXXX`) и передай его в `license_login`. Ключ не повторяй в ответах и не записывай в файлы.
- Есть `warning`: перескажи его человеку вместе со ссылкой на продление.
- `methodology: false`: этапы методики недоступны. Объясни причину из `message`. Наработки кандидата остаются, работать с ними и выгружать их можно.
- После продления ключа вызови `license_status` с `refresh: true`.

## 4. Работа

1. Вызови `status_report`: он показывает, на каком этапе кандидат и что делать дальше. Иди по этапам по порядку и не перескакивай. Процедуру этапа читай через `stage_procedure` с номером этапа.
2. Документы. Если человек прислал резюме или другой файл, вызови `document_import` с полным путём к файлу. Поддерживаются PDF, DOCX, PPTX, XLSX, HTML, TXT, MD, RTF. Старый `.doc` попроси пересохранить в `.docx` или PDF.
3. Вакансии. Источники и сбор — инструменты сборщика (`add_telegram_channel`, `vacancies_sync` и другие). Список Telegram-каналов по умолчанию приходит с методикой, свои каналы человек может добавить сам.

## 5. Вопросы и анкеты

Сначала узнай, где человеку удобнее отвечать: `ui_mode`. Если режим не выбран, спроси один раз: в чате или в окне браузера. Браузер: `ui_open` и открой ссылку своим встроенным браузером, если он есть, иначе `ui_open` с `external: true`. В чате, если умеешь показывать MCP Apps, вызови `ui_show`. Ответы со страницы сразу в базе: читай их через `intake_get`.

Анкету первого этапа задавай блоками через `intake_ask`: `pains` (8 трудностей), затем `situation_goal`, `situation_search`, `situation_limits`. Не повторяй вопросы, на которые человек уже ответил.

1. `intake_ask` сам показывает форму, если агент умеет формы MCP. Ответ сразу сохраняется.
2. Если вернулось `asked_by: "agent"`, формы не было или её закрыли. Задай эти вопросы сам: встроенным выбором вариантов (в Claude Code — инструмент вопросов, 8 трудностей разбей на два вопроса по 4 варианта с множественным выбором; в Codex `request_user_input` работает только в режиме плана) или нумерованным списком в сообщении.
3. Ответ передай в `intake_answer` как есть: «1, 3», выбранные варианты, «пропустить» или свои слова. Сервер сам разберёт ответ.

Перед подтверждением покажи человеку карту запроса из ответа и вызывай `intake_confirm` только после его явного «да». Другие вопросы задавай так же: выбор вариантов, если он есть, иначе нумерованный список.
