# hrs-collector

Сборщик вакансий JobShturman: HeadHunter, Telegram-каналы и LinkedIn за одной абстракцией адаптера. Одно ядро, три входа: HTTP API, MCP-сервер для агента и CLI. Контракт для других блоков описан в [CONTRACT.md](CONTRACT.md).

## Быстрый старт

```bash
cd collector
uv sync --extra telegram          # telegram extra нужен только для чтения через аккаунт
uv run pytest -q                  # 25 тестов

uv run hrs-collector import-telegram                     # реестр 210 каналов из ТЗ
uv run hrs-collector add-hh hh-cfo --text "финансовый директор" --area 113
uv run hrs-collector add-linkedin li-cfo --keywords "Chief Financial Officer" --location Dubai
uv run hrs-collector run --lookback 7 --budget 20        # собрать
uv run hrs-collector vacancies -q "финансовый директор"  # посмотреть
uv run hrs-collector show <vacancy_id>                   # карточка, источники, версии, дубли
uv run hrs-collector fetch-full <vacancy_id>             # полное описание hh.ru/LinkedIn

uv run hrs-collector serve --port 8765                   # HTTP API, OpenAPI на /docs
uv run hrs-collector mcp                                 # MCP по stdio
```

Данные лежат в `~/.hrs-collector/` (или `$HRS_COLLECTOR_DATA`): `collector.sqlite3` и, если настроен Telegram, `credentials.json` с правами 0600.

Подключение к Claude Code (`.mcp.json` в папке кандидата):

```json
{"mcpServers": {"hrs-collector": {"command": "uv", "args": ["--directory", "/path/to/collector", "run", "hrs-collector", "mcp"]}}}
```

## Переменные окружения

| Переменная | Зачем |
|---|---|
| `HRS_COLLECTOR_DATA` | папка данных |
| `HRS_COLLECTOR_TOKEN` | Bearer-токен для `/v1/*`; без него сервер слушает только loopback |
| `HRS_HH_ACCESS_TOKEN` | токен api.hh.ru для транспорта `hh_api` |
| `HRS_TG_API_ID`, `HRS_TG_API_HASH`, `HRS_TG_SESSION` | Telegram через аккаунт без файла credentials.json |
| `HRS_PACE_FACTOR` | множитель пауз между запросами к одному хосту (1 по умолчанию) |

## Почему так устроено

**Свои адаптеры, без Firecrawl.** Firecrawl и похожие сервисы рассматривал. Для этих трёх источников они не нужны и мешают:

- hh.ru отдаёт данные поиска и карточки как JSON внутри страницы, а официальный API требует токен. Рендерить страницу через сторонний сервис незачем.
- Telegram читается либо через публичное веб-превью `t.me/s/…` (чистый HTML с пагинацией и стабильным chat_id), либо через аккаунт кандидата по MTProto. Firecrawl второе не умеет вообще.
- LinkedIn гостевой поиск отдаёт готовые HTML-фрагменты.
- Каждая страница через Firecrawl стоит денег и отправляет поисковые запросы кандидата третьей стороне за рубежом. Для сервиса с персональными данными это вопрос ОР-10 ТЗ (трансграничная передача).
- Детерминизм и повторяемость проще обеспечить, когда разбор под нашим контролем и покрыт тестами.

Firecrawl имеет смысл позже, для сайтов целевых компаний (карьерные страницы с непредсказуемой вёрсткой). Его можно добавить ещё одним транспортом за той же абстракцией.

**Курсоры и покрытие** сделаны по `references/target_channels.md` §5 и ТЗ §13: сохранение страницы до продвижения курсора, незавершённый диапазон при нехватке бюджета, закрытие простоя от сохранённой точки, перепроверка правок в окне перекрытия, раздельные статусы `partial` / `no_access` / `no_new`. Сценарии приёмки из §8 закрыты тестами в `tests/test_acceptance.py`.

**Ничего не удаляется.** Изменённая публикация получает новую версию, дубли связываются через `canonical_id`, вакансия из нескольких источников хранит все источники.

## Что нужно от владельца

| Источник | Без ничего | Что даст доступ шире |
|---|---|---|
| Telegram | 200 из 210 каналов реестра с публичным @username читаются через веб-превью | `api_id` и `api_hash` с my.telegram.org и вход в аккаунт кандидата (`hrs-collector telegram-login`): нужны для 10 каналов без username и для каналов без веб-превью |
| HeadHunter | публичный поиск hh.ru работает | токен api.hh.ru: с весны 2026 анонимный API отвечает 403, приложение нужно регистрировать на dev.hh.ru и проходить модерацию |
| LinkedIn | гостевой поиск работает | официального API поиска вакансий для соискателей нет |

## Ограничения

- Отклики, переписка и подтверждения отправки не реализованы: сборщик только читает (`submit_action` и `reconcile_action` зарезервированы в контракте).
- hh.ru и LinkedIn могут ответить капчей или блокировкой анонимного трафика. Источник получит `captcha_required` или `rate_limited` с паузой, остальные продолжат работу.
- Поля `title`, `company`, `location` для Telegram извлекаются эвристикой из текста поста. Пост-подборка с несколькими вакансиями остаётся одной записью.
- `is_vacancy` — грубый признак по словам, не оценка релевантности.
- Гостевой доступ LinkedIn ограничен условиями площадки; держите `page_budget` маленьким и считайте источник дополнительным.
- Транспорты `telegram_mtproto` и `hh_api` написаны, но живым запуском не проверены: нет аккаунта и токена.
